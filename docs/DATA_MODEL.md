# Data Model

## Schema Design

The warehouse uses a star schema in Redshift. This design was chosen over a snowflake schema because the dimension tables are small enough (under 100K rows for merchants) that denormalization does not create storage concerns, and it reduces join complexity for analysts who are not advanced SQL users.

## Fact Tables

### fct_transactions

Primary fact table. One row per transaction event. Append-only with deduplication on load.
```sql
CREATE TABLE analytics.fct_transactions (
    transaction_id        VARCHAR(36) NOT NULL,
    transaction_ts        TIMESTAMP NOT NULL,
    transaction_date      DATE NOT NULL,
    merchant_id           VARCHAR(20) NOT NULL,
    card_token            VARCHAR(64) NOT NULL,
    amount_usd            DECIMAL(12,2) NOT NULL,
    currency_code         VARCHAR(3) NOT NULL,
    transaction_type      VARCHAR(20),
    channel               VARCHAR(20),
    country_code          VARCHAR(2),
    fraud_score           DECIMAL(5,4),
    fraud_decision        VARCHAR(20),
    is_fraudulent         BOOLEAN,
    chargeback_flag       BOOLEAN DEFAULT FALSE,
    processing_latency_ms INTEGER,
    ingestion_ts          TIMESTAMP DEFAULT GETDATE(),

    SORTKEY (transaction_date, merchant_id),
    DISTKEY (merchant_id)
)
;
```

**Distribution rationale:** merchant_id is the distribution key because the majority of analytical queries aggregate by merchant. This colocates all transactions for a given merchant on the same Redshift node, eliminating inter-node data shuffling.

**Sort rationale:** transaction_date is the leading sort key because nearly all queries include a date range filter. Redshift uses zone maps on sorted columns to skip irrelevant disk blocks during scans.

### fct_chargebacks

Chargebacks arrive days to weeks after the original transaction. Maintained as a separate fact table joined to fct_transactions via transaction_id.
```sql
CREATE TABLE analytics.fct_chargebacks (
    chargeback_id       VARCHAR(36) NOT NULL,
    transaction_id      VARCHAR(36) NOT NULL,
    chargeback_date     DATE NOT NULL,
    reason_code         VARCHAR(10),
    amount_usd          DECIMAL(12,2),
    status              VARCHAR(20),
    resolution_date     DATE,
    days_to_file        INTEGER,
    ingestion_ts        TIMESTAMP DEFAULT GETDATE(),

    SORTKEY (chargeback_date)
)
;
```

### fct_fraud_alerts

Real-time alerts generated by the Lambda scoring function.
```sql
CREATE TABLE analytics.fct_fraud_alerts (
    alert_id            VARCHAR(36) NOT NULL,
    transaction_id      VARCHAR(36) NOT NULL,
    alert_ts            TIMESTAMP NOT NULL,
    fraud_score         DECIMAL(5,4),
    alert_threshold     DECIMAL(5,4),
    analyst_action      VARCHAR(20),
    review_ts           TIMESTAMP,
    resolution          VARCHAR(30),
    ingestion_ts        TIMESTAMP DEFAULT GETDATE(),

    SORTKEY (alert_ts)
)
;
```

## Dimension Tables

### dim_merchants

Slowly changing dimension (SCD Type 2). Tracks changes to merchant attributes over time, particularly risk tier reclassifications, which require an audit trail.
```sql
CREATE TABLE analytics.dim_merchants (
    merchant_sk         INTEGER IDENTITY(1,1),
    merchant_id         VARCHAR(20) NOT NULL,
    merchant_name       VARCHAR(200),
    category_code       VARCHAR(10),
    category_name       VARCHAR(100),
    risk_tier           VARCHAR(10),
    onboarding_date     DATE,
    country_code        VARCHAR(2),
    city                VARCHAR(100),
    is_current          BOOLEAN DEFAULT TRUE,
    effective_from      DATE NOT NULL,
    effective_to        DATE DEFAULT '9999-12-31',

    DISTSTYLE ALL
)
;
```

### dim_date

Standard date dimension.
```sql
CREATE TABLE analytics.dim_date (
    date_key            DATE NOT NULL,
    year                SMALLINT,
    quarter             SMALLINT,
    month               SMALLINT,
    month_name          VARCHAR(10),
    week_of_year        SMALLINT,
    day_of_week         SMALLINT,
    day_name            VARCHAR(10),
    is_weekend          BOOLEAN,
    is_holiday          BOOLEAN,

    DISTSTYLE ALL
)
;
```

### dim_card_bins

Card BIN (Bank Identification Number) lookup. Maps the first 6 digits of a card number to issuing bank, card brand, and card type.
```sql
CREATE TABLE analytics.dim_card_bins (
    bin_prefix          VARCHAR(8) NOT NULL,
    issuer_name         VARCHAR(200),
    card_brand          VARCHAR(20),
    card_type           VARCHAR(20),
    issuing_country     VARCHAR(2),

    DISTSTYLE ALL
)
;
```

## Data Flow: Raw to Analytics
```
Bronze (raw Parquet from Kinesis Firehose)
  - Raw event payload, Kinesis metadata, ingestion timestamp
  - No transformations applied

Silver (validated and enriched)
  - transactions_clean: deduplicated, typed, nulls handled, schema-validated
  - transactions_enriched: joined with merchant profiles, velocity features computed
  - chargebacks_matched: chargebacks linked to original transactions

Gold (aggregated and analytics-ready)
  - fraud_scores_daily: daily aggregates by merchant, card BIN, channel
  - merchant_risk_profiles: rolling 30-day risk metrics per merchant
  - kpi_summary: platform KPIs computed daily

Redshift (warehouse)
  - COPY from gold layer into fact and dimension tables
  - Materialized views refreshed after each load
```

## Materialized Views

These views power the Power BI dashboards and are refreshed after each batch load.
```sql
CREATE MATERIALIZED VIEW analytics.mv_fraud_overview AS
SELECT
    t.transaction_date,
    m.category_name,
    m.risk_tier,
    t.channel,
    COUNT(*) AS total_transactions,
    SUM(t.amount_usd) AS total_volume,
    SUM(CASE WHEN t.fraud_score > 0.7 THEN 1 ELSE 0 END) AS high_risk_count,
    AVG(t.fraud_score) AS avg_fraud_score,
    SUM(CASE WHEN t.chargeback_flag THEN t.amount_usd ELSE 0 END) AS chargeback_volume,
    SUM(CASE WHEN t.chargeback_flag THEN 1 ELSE 0 END)::FLOAT
        / NULLIF(COUNT(*), 0) AS chargeback_rate
FROM analytics.fct_transactions t
JOIN analytics.dim_merchants m
    ON t.merchant_id = m.merchant_id AND m.is_current = TRUE
WHERE t.transaction_date >= DATEADD(day, -90, CURRENT_DATE)
GROUP BY 1, 2, 3, 4
;


CREATE MATERIALIZED VIEW analytics.mv_chargeback_trends AS
SELECT
    t.transaction_date,
    t.country_code,
    cb.reason_code,
    COUNT(DISTINCT cb.chargeback_id) AS chargeback_count,
    SUM(cb.amount_usd) AS chargeback_amount,
    AVG(cb.days_to_file) AS avg_days_to_file,
    PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY cb.days_to_file) AS median_days_to_file
FROM analytics.fct_chargebacks cb
JOIN analytics.fct_transactions t
    ON cb.transaction_id = t.transaction_id
WHERE t.transaction_date >= DATEADD(day, -180, CURRENT_DATE)
GROUP BY 1, 2, 3
;
```

## Incremental Loading Strategy

Fact tables use an append-with-deduplication pattern:
```sql
BEGIN TRANSACTION;

COPY analytics.fct_transactions_staging
FROM 's3://fraudshield-lake-prod/gold/fraud_scores_daily/dt=2024-01-15/'
IAM_ROLE 'arn:aws:iam::role/redshift-copy-role'
FORMAT AS PARQUET;

INSERT INTO analytics.fct_transactions
SELECT s.*
FROM analytics.fct_transactions_staging s
LEFT JOIN analytics.fct_transactions t
    ON s.transaction_id = t.transaction_id
WHERE t.transaction_id IS NULL;

UPDATE analytics.fct_transactions
SET chargeback_flag = TRUE,
    is_fraudulent = TRUE
FROM analytics.fct_chargebacks cb
WHERE analytics.fct_transactions.transaction_id = cb.transaction_id
  AND analytics.fct_transactions.chargeback_flag = FALSE;

TRUNCATE analytics.fct_transactions_staging;

END TRANSACTION;

REFRESH MATERIALIZED VIEW analytics.mv_fraud_overview;
REFRESH MATERIALIZED VIEW analytics.mv_chargeback_trends;
```

Dimension tables use truncate-and-reload for small, static dimensions (dim_date, dim_card_bins) and SCD Type 2 merge logic for dim_merchants.
